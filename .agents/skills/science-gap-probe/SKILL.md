# science-gap-probe

5段で進める。各段は、次の段へ渡すものができたら終わる。段を飛ばさない。

| 段 | すること | 次へ渡すもの |
|----|----------|--------------|
| 1 | 候補を広く並べる | 候補の一覧 (10〜20) |
| 2 | 候補ごとに現状を調べる | 現状の表と出典 |
| 3 | 検証できる問いを1つ選ぶ | 問い、正解表、対照の引き方 |
| 4 | 判定の手順を先に固定する | コミットされたスコアとテスト |
| 5 | 実データで試す | Recall と Inspection Load の表 |

分野だけが与えられたら 1 から、候補が与えられたら 2 から始める。

## 1. 候補を広く並べる

深さより幅。空白の種類が違う候補を混ぜる。

- 未解析のデータ: 観測済みで、再解析するだけで見つかるかもしれない
- 未実施の実験: 組み合わせが多すぎて人手では試しきれない
- 未接続の知識: 複数の分野にあるのに横断されていない

候補は問いの形で書く。「どのデータで、何を見つける、または当てるか」まで言えないものは、データ源の名前であって候補ではない。データ源しか思いつかなければ、そのデータで立てられる問いを2つ3つ書いて候補にする。

この段では、検証しやすい形の候補へ寄せたくなる。寄せてよいが、検証しにくい候補も落とさずに並べる。落とすのは段3の仕事である。

「注目度が低い」はこの段では推定でよい。推定であると書く。

## 2. 候補ごとに現状を調べる

1候補につき1回の検索を並列で投げる。検索語に、データ名、手法の総称、今年の年を入れる。上位がまとめ記事やブログで埋まったら、年を外して論文の検索に切り替え、もう1回投げる。資料がその国の言葉で書かれている分野は、その言葉と英語の両方で投げる。

候補ごとに表へ書くもの。

- 既にあるもの: 同じ問いを大規模に解いた研究、専用のモデル、事業者
- 公開データ: 認証の要否、大きさ、ライセンス
- 独立した評価器: 答えを AI 自身とは別の方法で確かめる手段
- 混み具合: 高は同じ問いを大規模に解いた研究や専用のモデルが上位に出る、中は関連する研究はあるが同じ問いではない、低は出ない

検索だけでは「公開データ」の欄がほとんど埋まらない。段3へ進める見込みのある候補を3つまで選び、配布元と利用規約のページを本文まで読んで埋める。残りは「未確認」と書く。

表の前に、根拠が検索の表題と抜粋であること、本文まで読んだものはどれか、検索しなかった候補はどれかを書く。出典の URL は候補の番号ごとに残す。

## 3. 検証できる問いを1つ選ぶ

選ぶ基準は [references/choosing.md](references/choosing.md)。

問いは「新しいものを見つける」ではなく「既に見つかっているものを、どれだけの手間で拾い直せるか」に置く。そのために正解表を探す。見落とし事例を一覧にした論文、後から確定した分類、配布元が付けた印、時点で分けた記録が使える。

このスキルが段5まで扱うのは、陽性の一覧と背景に分かれる検出の問いである。値を復元する問い (古い記録から気温を推定するなど) は、評価器が「重なる期間の観測との誤差」になり、Recall と Inspection Load の形に乗らない。その分野の中心が復元なら、検出の形に乗る問いを無理に探さず、段3で止めて、評価器と基準 (平年値、最近傍など) を書いて報告する。

正解表が見つからない候補も、この段で保留にする。評価器の無いまま 5 へ進まない。

正解表が実在するかは、実物を見ないと分からないことが多い。1件だけ取って確かめてよい。見るのは、行と列の構造、凡例、印の付き方までとし、スコアに使う値は見ない。何を見たかを書き残す。

選んだら、次の3つを書いてから進む。

- 正解表の出どころとライセンス、それがどう選ばれたか
- 対照の母集団: 人が正解表を探すときに目を通すことになるもの。全数が取れる大きさなら全数にし、標本は引かない
- 数える単位: 何を1件とするか (天体、地点と年の組など)
- Recall: 正解表のうち、しきい値を超えた割合。Inspection Load: 母集団のうち、しきい値を超えた割合
- この PoC が示せることと、示せないこと

## 4. 判定の手順を先に固定する

固定するのはスコアと判断の規則である。取得や解析のコードは、段5で実物を見てから書いてよい。

- スコアは、その分野の先行研究の基準から書き起こす。基準を記憶から書いたら、そう書く
- しきい値は、先行研究の値が自分の統計量にそのまま当てはまるときだけ使う。当てはまらなければ、しきい値を作らず、母集団の中での順位 (上位 1%、5%、10%、25%) で表を作る。雑音の模擬から作ったしきい値は、実データの「何も無い」を表さないことがある
- 判断の規則を書く。主張を1つ、どの結果なら支持しどの結果なら退けるか、退けられたときに変えてはいけないもの (しきい値、層、単位、除外)。根拠の無い数の閾値は置かず、向きと不確かさで書く
- 同じ結果を説明できる別の理由を並べる。循環 (正解表の選ばれ方とスコアが似ている)、観測の努力、標本の偏り、リーク、偶然
- 特徴量の計算は、合成データのテストを先に書く
- 正解表のデータを取得する前にコミットする。コミットできない場面では、スコアのファイルを書いた時刻と取得の時刻を控える

正解表の値を見てからスコアを直さない。直したくなったら、直す前の結果を残し、別の正解表で測り直す。規則を書いた時点で何を見ていたかを、見たものと見ていないものに分けて書く。

## 5. 実データで試す

1. 1件だけ取る。返る形、大きさ、時間を見る
2. 正解表の符号化を、答えの分かっている1件で確かめる。印の種類、凡例、記号の意味を取り違えると、結果は出るが意味が逆になる
3. 正解表の全件を取る。取れなかったものがあれば失敗として止める
4. 対照を引く。乱数の種を固定し、引いた一覧をファイルに残す
5. 同じスコアをかけ、しきい値ごとに Recall と Inspection Load を並べる。スコアが出なかった件数を層ごとに添える
6. 判断の規則を当てる。支持、退ける、判断できない、のどれかを書く

特徴量やモデルは足さない。落ちた正解がなぜ落ちたかを1件ずつ調べるのは、足すことに入らない。調べてよい。

実データを読む実行にはメモリと CPU の上限を掛け、長い取得は裏で流す。つまずきやすい点は [references/pitfalls.md](references/pitfalls.md)。

## 報告

- しきい値ごとの表をそのまま見せる。1つの数字にまとめない
- 対照が層別なら、層ごとに読む。全体の割合は実際の混合比ではない
- 分かったこと、分からないこと、測っていないことを分けて書く
- 「空いている」「混んでいる」の判断には、根拠の強さ (抜粋か、本文か、実測か) を添える

## 表が出た後

次の一手は、判断の規則の結果で決める。

- 支持: 基準の順位 (件数だけで並べるなど) と比べ、スコアが何を足したかを測る。その後に、設定を変えても結論が保たれるかを試す
- 退ける、または判断できない: スコアを直さずに止め、何が足りなかったか (データの種類、正解表の大きさ、母集団の引き方) を書く
- どちらでも、新しい候補を探す段階へ進む前に、合成した対象を入れて回収率を測る
