# 実データで試すときのつまずき

天文学 (ZTF のアラートを Fink の API で取る) と、気象 (気象庁の年ごとの表を HTML から読む) で1回ずつ走らせて出たもの。分野が変わっても同じ形で起きる。

## 取得

- エラーが理由を言わない。列の指定で 500 が返ったときは、列を減らして切り分ける
- 「0件」が複数の意味を持つ。データの無い期間も、途中で使われなくなった分類名も、同じ空の配列で返る。層ごとに 0 件の期間を並べると区別できる
- 出版社のサイトは自動取得を拒む。プレプリントのサーバーに同じ論文があればそこから読む
- 取得は遅い。1件数秒でも数百件で数十分になる。裏で流し、キャッシュを作業ツリーの無視対象に置く

## HTML の表から読むとき

- 印の意味は凡例とスタイルシートで確かめる。クラス名から推測すると逆に読むことがある
- 値に付く記号 (括弧、かぎ括弧、アスタリスク) は、欠測や準正常値を表す。数字だけを抜くと、信頼できない値が混ざる
- 罫線や色で表された印は、どの行に属するかを決めて書く (行の下の線は次の行との境か、その行の印か)
- 正解の印とデータが同じページにあると、正解表だけを先に取ることができない。構造だけを見る下見と、値を読む取得を分ける

## 対照

- 層別標本は実際の混合比ではない。層ごとに同数を引いたら、層ごとに読む
- 「最新の N 件」を返す API は、期間の終わりに偏る。期間を短く、N を大きく取る
- 層の定義が期間の途中で変わることがある。その層が代表している期間を結果に書く

## 評価

- 正解表が後から答えを持つ。論文の後に登録された分類は特徴量に使わない
- 手元のデータが論文と違う。観測点が極端に少ない正解は、手順の弱さではなくデータの差で落ちる。落ちた理由を1件ずつ書く
- 値が無いことを「条件を満たした」に数えない。欠測は満たさない側に倒し、欠測の件数を見せる
- 記録の端や、参照にできる相手が少ない時期の正解は、スコアが出ない。出なかった件数を Recall の分母から黙って外さない
