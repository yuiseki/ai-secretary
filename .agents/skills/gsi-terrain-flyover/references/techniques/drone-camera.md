# 地図動画のカメラ設計：ドローン空撮の応用

## 各シーンで選ぶ

1. そのシーンで何を理解してほしいかを一文で決める。対象、話の段階、範囲、見せたい前後関係を明確にし、必要なランドマークとラベルを選ぶ。
2. 少なくとも静止を含む複数の候補を考え、集中、位置関係、経路、立体感、景色の出現のどれを優先するかで比較する。開始と終了の構図、対象の画面位置、説明や章の切り替えとの関係を決める。静止単独も妥当な選択であり、動きの数を増やすこと自体を目的にしない。
3. 最も効果的な技法または組み合わせと選択理由、開始・中間・終了の状態、時間、周辺ラベル、必要な地形・建物・時系列素材、実装上の制約をショット設計に記録する。ショット JSON に未対応のキーを追加して実行時に読まれると思い込まない。既存の企画・ショット一覧や別の設計メモに記す。
4. 画面上の移動を元の地理、発話、前後のショットにつなぎ、サンプリングした静止画と通常速度の動画で確認する。[camera-and-label-review.md](../camera-and-label-review.md) のラベル、加減速、タイル、写真の接続線の確認も行う。移動距離に比べて尺が足りなければ、移動量を減らす、尺を増やす、複数ショットや編集点に分ける。

基本の考え方は、寄る、引く、追う、回る、真上から見る、隠れたものを見せる、高さを変える、の7系統に整理できる。名称同士は重複し、ドローニーは後退・上昇を伴うプルアウェイ、360度オービットはオービットの一形態。実際に動かす要素を見極めて選ぶ。

## テンプレートのカメラでできること

標準の MapLibre テンプレートは `center`（地図上の注視中心）、`zoom`、`pitch`（0 が真俯瞰、数値が大きいほど斜め）、`bearing` を `from`・`to` または `keys` で補間する。画角を固定した地図カメラなので、`zoom` の変更は実機の光学ズーム、独立した前後移動、垂直上昇のいずれとも等価ではない。以下の「近似」は画面上の効果を意味し、厳密な飛行経路を保証しない。独立したカメラ位置・高度・画角、動く被写体、建物の立体モデル、異なる時刻の実写素材などが必要なものは、別途対応する実装・素材がある場合に限る。

| 技法 | 地図動画での使いどころと実現方法・制約 |
|---|---|
| ドリーイン／プッシュイン | 主題に注意を集める。対象へ `center` を合わせつつ `zoom` を上げて近づくように見せる近似。対象に寄り過ぎて周辺の位置関係を失わないようにする。 |
| ドリーアウト／プルバック | 周囲のランドマークとの関係を明かす。対象を見失わないよう `zoom` を下げ、必要なら `center` を移す。 |
| トラッキング | 船やルートの移動を追う。動く対象の時刻と位置を用意し、カメラの `keys` を同じ時間軸で合わせる。静的な線の描画を追うことはできるが、それだけで実際の船・車・人の動きにはならない。 |
| サイドトラッキング | 川や道路沿いの経路と両岸を比較する。進路に沿って `center` を移し、見せたい方向に `bearing` と `pitch` を調整する近似。動く対象に並走するにはその軌跡が必要。 |
| フライオーバー | 川、橋や街区の上を通り抜けるように全体のつながりを見せる。地図の中心を対象に沿って移す近似。建物より上を実際に通過したと断言できない。 |
| クレーン／ジブ | 高さの変化で周囲を見せる。`zoom` や `pitch` による構図変化で近似する。垂直のカメラ高度は独立して指定できない。 |
| ホバリング | 情報の読み取り、比較、説明を優先する。始点と終点を同一にし、必要な地名や図を静止させる。 |
| オービット | 対象と周囲の向きを変えながら立体的に見せる。対象付近を `center` に保って `bearing` を変える近似。地表や投影中心を回るため、実機の一定半径の軌道ではない。地形や建物の立体データが不足すると効果は乏しい。 |
| 360度オービット | 上記の一周。`bearing` は隣り合うキー間で短い方へ回るので、0→360 の2点だけでは一周しない。例えば 0→90→180→270→360 のように各差を180度未満にした複数の `keys` を使う。対象とラベルの可読性、速度、全区間の建物・地形を確認し、説明に必要なときに使う。 |
| ヘリックス／スパイラル | 回り込みと構図の広がりを同時に伝える。オービットに `zoom` や `pitch` の変化を重ねた近似。実際の螺旋軌道や垂直移動の再現ではない。 |
| パララックス | 前景と背景の奥行きを示す。斜め視点で `center` や `bearing` を少し動かし、地形や立体建物の視差を利用する。平坦なオルソ写真だけでは実物の壁や樹木の視差は得られない。 |
| リビール | 観客が対象や周辺を段階的に発見する構図。移動・傾き・地形の遮蔽を組み合わせ、どこから何が現れるか設計する。隠す立体物がないとき、単に画面外から入れる動きは遮蔽によるリビールと区別する。 |
| ライズアップ | 手前を越えて景色を見せるリビール。立体地形などの遮蔽と `zoom`・`pitch` を組み合わせて近似。独立した垂直上昇は標準ではできない。 |
| プルアウェイ | 主題から引いて周辺とのスケール差を示す。プルバックの用途を主題と広域の関係に置いたもの。 |
| ドローニー | 主題を保ちながら後退・上昇し、周辺を現す。`zoom` と `pitch` を調整する近似。人物の実写追跡や厳密な後退・上昇とは区別する。 |
| チルトリビール | 下向きから遠方へ視線を移す。`pitch` を上げる近似。MapLibre では中心などとの関係も変わり、カメラ位置を固定した実機のチルトとは限らない。地平線付近の素材欠けや歪みも確認する。 |
| トップダウン | 道路・川・区画の形と位置関係を読み解く。`pitch: 0` で真俯瞰にする。 |
| バーズアイビュー | 広い範囲の地物の配置を見せる。`zoom` を下げ、真俯瞰または適度な斜め視点にする。 |
| エスタブリッシング | 場面の舞台を説明する。広い構図と周辺ランドマークを用意し、必要なら次の主題へ寄る。ショットの役割であり、特定の動きに限定しない。 |
| パノラマ | 広がる風景を順に見せる。`bearing` の変化で方向転換を近似できるが、地図の注視中心まわりにカメラが動くため、固定位置からの水平パンを保証しない。 |
| フライスルー | 開口部や物の間を通って奥行きを見せる。標準テンプレートの標高と地図カメラだけでは開口部の通過や衝突判定を保証できない。適切な立体モデルと通過可能なカメラ制御が別途必要。 |
| FPV | 飛行者の視点で移動を体験させる。標準の地図カメラで近い進行方向の画は作れても、実機の姿勢や自由なロールを伴う FPV 飛行ではない。速度感を目的に急旋回を常用しない。 |
| ダイブ | 急降下の迫力を出す。`zoom`・`pitch` の急変は視覚的な近似にとどまり、独立した垂直降下ではない。説明動画では可読性や酔いを優先し、必要な場面に限る。 |
| ドリーズーム | 対象の大きさを保ちつつ背景の遠近感を変える。カメラ距離と画角を独立に変える必要があり、標準テンプレートでは実現できない。単なる `zoom` 変更をドリーズームと呼ばない。 |
| ハイパーラプス | 時間と空間の変化を同時に圧縮する。カメラ移動を早めるだけでは時間経過は生まれない。時刻の異なる対応素材と時間軸がある場合に限って表現し、素材の時点と切り替えを明示する。 |

## 組み合わせの例と選択理由

- **川と街の位置関係を導入する**：エスタブリッシング＋バーズアイで川・主要駅・橋を同時に見せ、主題に移る必要がある箇所でゆっくりプッシュイン。地域の広がりが説明の中心なら、寄らずにホバリングする。
- **川沿いの移動を説明する**：サイドトラッキング＋鳥瞰で線と橋を追う。経路が実在・推定のどちらかを示し、線の描画とカメラが同じ時間軸になるようにする。
- **ランドマークを周囲に結びつける**：短いオービット＋パララックスで建物と川・駅の位置関係を示し、その後ホバリングして地名を読ませる。立体素材がない場合は真俯瞰やプルバックを選ぶ。
- **一地点から街全体を明かす**：プルアウェイ＋クレーン風の近似。地図の `zoom`・`pitch` による構図変化であることを踏まえ、対象と周辺を段階的に見せる。
- **地形の背後を見せる**：リビール＋ライズアップ風の近似。実際に地形が手前を隠す構図を確認する。遮蔽がなければバーズアイやプルバックを選ぶ。

`ease` はショット全体の時間に適用され、その後 `keys` の区間ごとに線形補間される。複数キーの距離・角度・時間幅が不均等だと途中で速度が変わる。キー間の急な方向転換、長距離移動での加速、ラベルや字幕の重なり、3D タイルの遅延出現を動画で確認する。地図を動かす際も、写真枠から撮影地点へ向かう線と地物ラベルが正しい位置を保つようにする。
