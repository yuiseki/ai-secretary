# 地理動画を企画から完成まで作るとき

## 構成と章のつなぎ

- 依頼の主題・体験を軸に、導入、論点、比較、結びの流れを作る。複数話者の既存実装があれば先に調べ、指定されたキャラクター、話し方、声を尊重する。10分以上などの長さは実音声の合計と編集点で確認する。
- 前章の最後に前の発見を受ける問い、次章を予告する答えなどを入れる。章をまたいで同じ問いを繰り返さない。自然な会話は残し、既存の声と字幕の対応を保つ。
- 章の間は、必要に応じて無音のタイトルカードを編集点にする。音声・BGM を章をまたいで切らない指定がある場合は、それを優先する。
- 複数章は各章のショット JSON から独立に生成し、同一仕様の動画・無音カードとともに結合する。`template/chapter_pipeline.py` はこの処理を行う。指定がなければ最大3並列を目安に、全体を1つのメモリ・CPU制限スコープ内に置き、タイル提供元と機械の負荷に応じて減らす。
- 台本、場面、ショット、音声、素材、各章の並びを対応づけて記録する。章の再利用はショット JSON だけでなく、参照画像・フォント・音声設定と音声エンジン、レンダラー、地図・タイルの内容と版まで同一である場合に限る。外部タイルは同じ URL でも更新され得るので、必要に応じて利用時のデータを保存・記録する。テンプレートのパイプラインは安全のため章の自動再利用をしない。

## マニフェストと実行

各章 JSON は通常のトップレベル仕様を持ち、少なくとも音声付きの `lines` を含む。プロジェクト直下に次の形の JSON を用意し、`spec` はプロジェクトからの相対パスにする。各章のスクリプトとショットが全て対応していることを事前に確認する。

```json
{
  "series": "番組名",
  "cardSeconds": 2.5,
  "chapters": [
    {"id": "intro", "title": "導入", "spec": "shots/intro.json"},
    {"id": "chapter-1", "title": "第1章", "spec": "shots/chapter-1.json"}
  ]
}
```

```bash
systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 -p CPUQuota=400% -- \
  python3 chapter_pipeline.py chapters.json --out out/新しい版 --workers 3 --check-label-overlap
```

Pillow、Noto Sans CJK、ffmpeg、ffprobe、Node.js、Playwright、VOICEVOX が必要。各章は 1920×1080・24fps・H.264/AAC stereo で統一し、結合後に全編を音量正規化する。完成物は `episode.mp4`、章の開始秒は `chapters.json`。このパイプラインは BGM を混ぜないため、`bgm` 指定があれば停止する。BGM が必要なら結合後に権利と音量を確認して別途重ねる。既存の出力先は上書きしない。`--voice-cache` は既存キャッシュを章ごとに複製し、並列書き込みの衝突を避ける。実行中にタイル取得・ブラウザー・時間切れのエラーがあればログを確認し、修正して新しい出力先で再生成する。

## 地図、写真、利用条件

- 国土地理院の空中写真は時代の比較に使えるが、継ぎ目・欠落・撮影年代の幅に注意する。背景が過去、ラベルが現代の場合は画面と概要欄で明示する。
- 地名は対象の場所だけでなく、隣の駅・川・橋など、位置関係の理解に役立つランドマークを加える。`osmLabels: true` は `tile.yuiseki.net` の現代の OpenMapTiles 地名を重ねる。ユーザーの環境でサービスが利用できるときに使い、提供者表記を確認する。主題の施設は補助ラベルで明示する。
- `nominatim.yuiseki.net` で座標・地物種別・範囲を調べ、`importance` は複数の候補を選ぶ補助にする。重要度だけで主題や近隣駅を除外しない。Overpass は OSM の地物・路線形状の取得に、Valhalla は対応する移動手段の経路計算に使える。徒歩経路を鉄道の実線形として描かない。地名・位置とデータ更新時刻を確かめる。
- 画像の重複を台本・ショット一覧で先に監査し、同じ写真を繰り返し使わない。必要な再登場が明示された場合は、前後の目的・表示方法を変えて意味を持たせる。無関係な写真で話題を代用せず、適切な写真を探すか、説明用の地図にする。
- ユーザー指定の素材・引用元・撮影者表記を優先し、素材ごとに作者、取得先、ライセンス、加工、引用箇所を記録し、必要な出典を画面と概要欄に示す。ある写真群に与えられた CC0 を、他者の写真や全素材に広げない。自分の写真の撮影者を yuiseki と指定された場合はそのとおり表記する。
- Gyazo で利用者が指定した撮影日・写真を探すときは gyazo スキルを用い、元画像の EXIF を確認する。GPS は撮影地点の概略であり、被写体の位置・人物の進行方向を保証しない。

## 写真と地図の対応

`photo_geo.py` の `exif_coordinates` は EXIF の GPS を `[経度, 緯度]` に直し、欠損や範囲外ならエラーにする。`linked_photo(..., credit=...)` は `photo_marker` を作る。`at` に写真の撮影地点を入れると、写真枠からの線が常にその地点を指す。写っているランドマークの地点を `cameraAt` と `cameraLabel` で示す（歴史的なキー名であり `cameraAt` は撮影地点ではない）。必要な地物名は分かる名前で示し、「撮影地点（EXIF）」の不要なラベルは付けない。GPS の誤差、地図と実際の橋・建物の関係を確認し、特定できないときは推測を事実として表示しない。

MapLibre の `map.project` をカメラ更新後・各フレームで呼ぶため、画面上の線の終点はカメラの移動・回転・拡大縮小に追従する。連続する複数の時刻で実際の映像を見て、線が撮影地点を外さず、写真枠・字幕・立ち絵・地名と干渉しないことを確認する。

## 最終確認と配布

- ショット一覧を点検し、静止・寄り・引き・移動・俯瞰・写真・図解を内容に合わせて使い分ける。特定の参考動画のカメラの動きを求められたら、実際の映像とショットを確認する。参考映像そのものや素材を許可なく再配布しない。
- 章境界は音声込みで通して見聞きし、会話、無音カード、場所とカメラの到着が自然につながるか確認する。動画の冒頭・途中・末尾や章境界で、地図の欠け、ラベルの重なり・画面外への消失、字幕・写真・立ち絵の干渉、出典と読み間違いを確認する。
- 完成動画の長さ、映像・音声のストリーム、各章の開始秒、出典を記録する。`v0.1.7` など版番号をファイル名に入れ、既存版を上書きしない。公開はユーザーの具体的な依頼と既存の継続的な許可に従う。許可済みの配布先がある場合は配置し、コピー元との一致と URL の応答を確認する。
- YuisekinTV の今回の継続依頼では `/sata_hdd_24tb/www/html/static/tmp/YuisekinTV/` が `https://z.yuiseki.net/static/tmp/YuisekinTV/` に対応する。ただし、別の案件に配布許可が自動で広がるわけではない。

## 試作を求められたとき

写真と地図を線で結ぶような新しい表現について、利用者が先に試作を求めた場合は、代表的な写真1枚と実際の位置を使った短い試作を先に提示する。静止画で構図と意味を合わせ、動きが必要なら短い動画で追従を確認してから本編に適用する。
