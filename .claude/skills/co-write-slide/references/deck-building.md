# デッキを作るときの具体的な注意

SKILL.mdのフェーズ1を、Marpで実際に回したときに分かったこと。2026-09と2026-10の社内勉強会のデッキ作りから。

## 材料の探し方

- GitHub: `gh search prs/issues/commits --author <本人> -- -org:<会社のorg>`。社内向けの発表で会社のorgの活動を話す意味は薄いので外す。コミット検索は1,000件で打ち切られるので、日付で区切って取る。Issueは本文とコメントまで読む。
- WebのPDFは取得ツールで本文が読めないことがある。手元にダウンロードして `pdftotext` で読む。
- 画像の文字はGyazoのOCRで読める(`gyazo get <id> --json`)。

## スクリーンショット

- ブラウザのタブ、URLバー、ブックマーク、OSのタスクバーは切り落とす。参加者の名前やメールアドレスが写り込んでいる。
- 画面の数字を説明に書くときは、画面から読み取った値をそのまま使う。
- 2枚並べるときは幅で指定する(16:9で各540px前後)。1枚のときは高さで指定する。幅で指定すると縦長の画像が下にはみ出す。

## 既存のデッキの再利用

過去の登壇資料をコピーして直さない。元のデッキから毎回読み込んで組み立てるスクリプトを書き、画像のパスを付け替える。元を直せば組み立て直すだけで反映される。

## Marpの罠

- 本文の行の直後に `---` を置くと、区切りではなく見出し(setext)になり、2枚が1枚に結合する。`---` の前後には必ず空行を入れる。
- 既定のテーマは縦中央に寄せる。表紙以外は `section:not(.title) { place-content: start stretch; }` で上詰めにする。
- `<!-- _style: ... -->` は効かないことがある。収まらないときは表の行をまとめる。
- PDFやPNGの書き出しにはPlaywrightのChromiumを使う。snapのChromiumは `/Workspaces` を読めず、画像の抜けた成果物ができる。Ubuntuでは `CHROME_NO_SANDBOX=true` が要る。
- marp-cliは標準入力を閉じて実行する(`</dev/null`)。開いたままだと入力待ちで止まる。

## 見て確かめる

- 全スライドをPNGに書き出し(`--images png`)、一覧画像にして見る。
- 日本語の推敲(yomiyasuなど)をかける。太字とダッシュ記号は使わない。和文と英数字の間の空白、行末のコロン、比喩動詞を直す。チップとHTMLとコードには触れない。
